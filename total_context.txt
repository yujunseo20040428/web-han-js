1. 응답 해석
네가 받은 데이터는 다음과 같아.

01 00 0C 00 00 00 00 ...
현재 확인할 수 있는 것은 다음과 같아.

전송 바이트: 33 → HIDAPI가 Report ID를 포함해 33바이트를 전송했어.

응답 첫 번째 바이트: 01 → 응답 Report ID로 해석할 수 있어.

응답 데이터: 00 0C ... → 명령 응답 데이터가 도착했어.

즉, 통신 경로 자체는 정상 작동하고 있어.

다만 0C를 프로토콜 버전이라고 단정하면 안 돼. 응답의 필드 구조를 공식 코드와 대조해야 해.

0x3C, 0x5A → 16진수 기준 각각 60, 90이 아니라 10진수 60, 90

즉, 현재 확인된 것은 다음과 같아.

Python에서 키보드의 커스텀 HID 인터페이스로 명령을 전송할 수 있음.

키보드가 명령 번호 12, 13을 인식하고 응답함.

매크로 관련 정보를 조회하는 프로토콜이 존재함.

다만 이 결과만으로 Python이 키보드에 임의의 키 입력을 실행시킬 수 있다고 확정할 수는 없어. 매크로 저장·설정 명령과 매크로 실행 명령은 별개일 수 있기 때문이야.

확인할 중요한 부분이 있어. 매크로 저장 공간은 60바이트가 아니라 15,450바이트야. 웹 프로그램의 JavaScript 코드를 확인해 보니 크기를 다음과 같이 계산하고 있어.

(a[1] ?? 0) << 8 | (a[2] ?? 0)

따라서 60, 90은 16비트 숫자 0x3C5A, 즉 15,450바이트를 의미해.

현재 확인된 결과는 다음과 같아.

매크로 슬롯 수: 31개

매크로 저장 공간: 15,450바이트

매크로 데이터 읽기 명령: 14

매크로 데이터 쓰기 명령: 15

이제 실제 저장된 매크로 데이터를 읽어 볼 수 있어. 읽기 명령은 설정을 변경하지 않는 조회 작업이야.

다음은 저장된 매크로 데이터의 첫 28바이트를 읽는 테스트야.

# 매크로 버퍼의 첫 28바이트 조회
packet = [0, 14, 0, 0, 28] + [0] * 28

written = dev.write(packet)
response = dev.read(64, 2000)

print("전송 바이트:", written)
print("매크로 응답:", response)

if response:
    print("매크로 데이터 HEX:",
          " ".join(f"{b:02X}" for b in response[4:32]))
